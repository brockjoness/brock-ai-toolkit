# Contributing

This isn't a product — it's the working set of tools I run my own stuff on, sanitized so other operators can read and pull from it. You don't need to contribute. Fork it, take what's useful, change it however you want.

If you do want to send something back:

- **Bug or sharp edge?** Open an issue. Be specific — what you tried, what broke.
- **New skill or improvement?** Open a PR. Keep each skill self-contained in its own folder with a one-page README.
- **Different way to think about a problem?** Email me. I'd rather hear how you'd approach it than argue about my code.

A few ground rules if you do PR:

- No secrets in any file, ever. Reference env vars instead.
- No real client data, names, or identifiers. Use obvious fakes (`Jane Doe`, `ACME Corp`, `jane@example.com`).
- Mark experimental things experimental. Don't oversell maturity.
- Keep skill READMEs under one page. Plain prose beats jargon.
